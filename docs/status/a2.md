## Implementation and handoffs

- `services/courtcam-adapter/calibration.py:calibrate(request)` and stdlib server `:8050/calibrate`; local demo also exposes `/api/calibrate`. Contract-valid tabletop H and optional approximate pinhole geometry. Degenerate taps fail explicitly. Four coplanar corners remain untrusted for airborne height. Known rectified intrinsics plus independent elevated validation points are required for metric trust. Solver truthfully says `opencv-planar-v1`, not courtcam; no dependency was falsely attributed.
- `rulepacks/table_tennis.yaml` provides metric field/landmarks/lines with tabletop z=0. The illustrative scene uses floor z=0/table z=.76, explicitly separate from rule coordinates. Empty rules prevent unsupported automatic calls; authoritative engine handoff is `services/flight/referee.py`.
- `flight/recording.py`, `flight/blurball.py`, `flight/stereo.py` preserve native time/frame identity, emit pixel measurements/missing data, separate upward-only toss geometry, and reject unsupported metric reconstruction. Stereo requires trusted rectified cameras, explicit clock maps and calibration/pixel/timing bounds. No reference ball ground truth enters inference.
- `tools/play_clip.py` implements source PTS/seq → C0 frame bus, optional calibration fixture, with a shared game epoch and explicit offset. `framebus_probe.py` inspects the bus. Redis was unavailable in the reused environment, so actual Redis publication/probe was not exercised.
- `tools/export_tt_observations.py` exports **62** selected-hybrid measurement events and **2,154** 10 Hz metadata-only track samples across the common overlap. All 62 envelopes and type-specific payloads validate against C0 schemas. Stable IDs, camera/game identity, source seq/PTS/time base, uncertainty limitations and evidence references are preserved. Detector ranking scores remain separate; rule-hint confidence is zero rather than fake calibrated certainty.
- Its `--publish` path calls `ObservationWriter` for every event and `TrackSampleWriter` for tracks, checks delivery counters/errors and requires service configuration. **No live Spacetime delivery is claimed**: that service/module/token is not configured in this checkout. Video never enters the shared-state payload.
- Production contract conflict: current `ServeTossPayload` still describes `max(rise,fall)` and requires contact even when unavailable. This demo intentionally does not fabricate schema-compatible official serve measurements. Agent 1/3 handoff: add upward-only angle/estimator profile, release interval, unavailable evidence and provenance; migrate consumers together. No shared schema was silently changed.
- `referee.py` is deterministic and separate from perception: supported evidence adapters, score/service/game/match progression, lets, missing/conflicting evidence, explicit human resolutions, idempotence and audited corrections. It does not infer a winner from disappearance or a pose. Local audit persistence is atomic/fsynced; explicit request IDs dedupe and conflicting reuse fails. Corrections A→B→A work; challenges preserve an existing valid score.
- `apps/tt-demo` uses bundled Three.js and procedural connected skinned bodies, with a surface-grid shader that deforms with the mesh. Raw joints remain separate from bounded display priors/smoothing. Orbit/zoom and source-camera/overhead/serve/edge presets work. Body/paddle position is illustrative; hand/face/racket orientation differs from the reference and is not evidence. Unsupported ball positions remain hidden. Original source close-up is the decisive evidence view.

# Decisions

Record significant architecture changes: `D-n: decision. Why. Date/owner.` These are working defaults that agents may revise with evidence and updated consumers/docs.

- **D-1: Flexible compute, with a cloud deployment baseline.** GCP `g2-standard-8` (L4, us-west1) for live processing and Vultr L40S for post-game work are current defaults. Local development, tests, inference, training and rendering are allowed on capable hardware; providers may change within authorized resources and budget. Historical credit estimates must be checked before spending. Why: hardware and budgets change. (2026-10-23)
- **D-2: Capture is a PWA, not native.** It runs on any iPhone or Android. Consequences: about 30 fps on iOS, no vibration (beep + flash instead), no 120 fps (slow-mo comes from interpolation). (2026-10-22)
- **D-3: Three perception families × rule packs.** Flight, possession and resting-object pipelines; each sport is a YAML pack with CEL conditions. Why: share perception work across 28 sports. (2026-10-22)
- **D-4: Honest call tiers.** AUTO ≥ 0.90 / BETA (challengeable, shows uncertainty) / PLAYERS DECIDE. Line calls use P(in) = Φ(d/σ). Fouls get evidence mode only. (2026-10-22)
- **D-5: The decision chain is SubQ Snap → Gemini → Claude votes → geometry.** Probabilities are temperature-calibrated on labelled calls. Decision models never make raw visual line calls. (2026-10-22)
- **D-6: SpacetimeDB is the current live game backend** (tables + reducers; the TypeScript SDK on clients; the Python engine calls reducers over HTTP). Redis stays internal for high-rate events. Why: shared real-time state for phones, the engine and viewers. Alternatives remain open if they improve the product. (2026-10-23)
- **D-7: The house-rule compiler is a Factory Droid** (sandboxed, triggered by a SpacetimeDB row, replay-tested, plan/diff/tests visible, human approval). Fallback: Claude only. (2026-10-23)
- **D-8: Moss for rulebook lookup and play search.** Firecrawl → one index per sport. (2026-10-23)
- **D-9: Build on Replay and courtcam.** Agents may extend Replay's ideas and adapt, copy or vendor compatible licensed code across its app, render, service and infrastructure layers. Preserve required notices and record incorporated sources/revisions. Trophy Watch currently targets the web; other interfaces remain possible. Why: reuse useful work and spend effort on Trophy's improvements. (2026-10-23)
- **D-10: White table-tennis balls** (BlurBall is trained on white). (2026-10-22)
- **D-11: Agent autonomy with focused safeguards.** Plans, owners, branch conventions, version pins and schedules are adaptable. Agents can make routine reversible choices without approval; protect credentials, privacy, licenses, honest results, user work and authorized resource limits. Why: reduce unnecessary restrictions while preserving trust and control. (2026-10-23)
- **D-12: M1 runs natively on the Apple M5 Pro.** Each Python service gets its own `uv` venv (py3.11; courtcam-adapter py3.12), and a `Procfile` + `make dev` starts them. `docker-compose.yml` remains the Linux/AWS deployment path. Why: Docker on macOS can't reach the Apple GPU or Neural Engine (MPS/CoreML). (2026-10-23, planning lead; see `docs/plan/three-agent-plan.md`)
- **D-13: In M1, frames travel as JPEG on Redis streams (`frames:{cam_id}`).** Shared-memory rings are deferred. Why: the stream works across venvs, processes and hosts, so perception can move to an AWS GPU later unchanged, and the clip player writes the same format. A recorder persists the stream as 2 s segments for replay. Shared memory can return for raw 720p on a GPU box behind the same reader API. (2026-10-23)
- **D-14: Only the engine writes to SpacetimeDB.** Clients read through subscriptions (`@trophy/state-client`) and write through the gateway, which XADDs `ctl:engine` commands. Perception reads only Redis. Why: one writer and one authorization point, and the gateway and perception have no SpacetimeDB dependency. (2026-10-23)
- **D-15: M1 is live ping pong + recorded basketball, both developed against CC BY clips first.** Cornhole is out of scope (user outline, 2026-10-23). Why: ping pong has the most-disputed measurable call (the edge rule) plus the serve rules, and basketball 2/3-pointers exercise the people stack. Developing on clips such as the [ping pong club match](https://www.youtube.com/watch?v=7maQFqJ3XQ0) with its disputed edge ball at 8:36, and the [half-court game](https://www.youtube.com/watch?v=2NxcgKW7xFM) with a score overlay, takes recording sessions off the critical path. Risk: BlurBall asserts CUDA and its weights license is unstated, so a classical tracker is the baseline and an AWS L4 the fallback. (2026-10-23)
- **D-16: The SpacetimeDB module is written in TypeScript** (SpacetimeDB 2.13, verified 2026-10-23), and the clients use the npm `spacetimedb` SDK through `@trophy/state-client`. Why: one language and shared types across module, bindings and frontends. The fallback is a gateway-WS fan-out behind the same interface (OPEN-1). (2026-10-23)
- **D-17: Trophy identifies fouls (this revises D-4's "fouls are never called").** *Measurable violations* (serve toss height/angle, kitchen volley, edge/side, outs, reach-over-net with ball contact) go through the normal confidence gate and may be AUTO. *Judgment fouls* (for example basketball personal contact) become `foul_flag` calls, capped at BETA and never AUTO. They show their probability and evidence (who moved first, minimum distance, contact frame), and players accept or overturn them. Why: the product outline asks for a referee that identifies fouls, while honest confidence still applies. (2026-10-23, user outline)
- **D-18: Perception emits measurements; only rule packs decide.** Events carry geometry with uncertainty (bounce position and σ, signed line distances, edge-class probabilities, feet-to-zone distances, release position vs. the arc). CEL conditions and scoring templates in `rulepacks/*.yaml` turn them into calls. Why: the Droid "add your own rule" compiler only edits YAML over a stable event vocabulary, and one engine serves every sport. (2026-10-23)
- **Scope (2026-10-23, user outline):** basketball (2/3-pointers, fouls, outs); ping pong (illegal serves: toss ≥ 16 cm and within 30° of vertical as a house tolerance, the edge rule); two-hand touch football; pickleball (kitchen, outs); tennis and badminton (outs); volleyball (hand over the net, outs); the Droid house-rule compiler; replay features. Other catalog sports, including cornhole, are out of scope for the current plan.
- **D-19: The stack is chosen for the Cal Hacks 13.0 prize tracks.** Spacetime is the sole real-time backend (not Convex). Cartesia handles voice (Sonic TTS + Ink-2 STT; this replaces Deepgram). The Factory Droid SDK is the house-rule compiler, triggered by `house_rule` rows. `decide()` fans out to **Claude, Gemini and Bitdeer Model Studio** voters blended with geometry, and the judge confirms (this replaces SubQ Snap; it revises D-5). Ask the ref uses an **Apify actor → Moss → Claude** (this replaces Firecrawl; it revises D-8). The domain comes from an MLH partner, and **Vultr** is the GPU fallback. Why: the user confirmed the official track list on 2026-10-24, and SubQ, Firecrawl and Deepgram are not sponsors. The compiler service may also write to Spacetime, but only house-rule progress (this extends D-14). (2026-10-24)
- **D-20: Demo-weekend cut.** MUST: live ping pong (rally scoring + edge rule), spoken calls, challenge → replay → AI votes, Droid house rules, voice ask-the-ref. SHOULD: recorded basketball 2/3, the CC BY ping-pong clip as a backup. STRETCH: serve toss, pickleball. CUT: the other sports (shown as "coming next"), basketball fouls, multi-angle, Trophy Watch. Why: a fixed hackathon deadline. (2026-10-24)
- **D-21: Spacetime holds the shared world state; video never goes into it.** Frames stay on the Redis frame bus and in the local recorder. Vision modules turn video into sport-agnostic metadata: `observation` rows (every event, with time, position in court metres, σ, confidence, camera) and down-sampled `track_sample` rows (10 Hz, rolling 120 s). They write these to Spacetime, so every phone, the dashboard and every agent (engine, Droid, LLM judge, ask the ref) share one record. Adding a camera adds rows; a new sport needs a vision module emitting the same vocabulary, plus a rule pack. The engine keeps a Redis hot path carrying identical event JSON. "An LLM judge that adapts to any sport" works at two speeds: deterministic rule packs make live calls, while LLMs write rules for new sports and house rules (Droid + Moss clauses), give second opinions on close calls, and explain verdicts. Still open (OPEN-10): the vision module per sport family and the metadata beyond ping pong. Why: the team's Spacetime direction (2026-10-24), plus scalability. (2026-10-24)
- **D-22: Ping-pong illegal-serve rules (house values from the user).** The toss must rise **more than 6 in (0.1524 m)** after leaving the open palm, and the ball's path **from the hand to the hit must stay within 30° of vertical** (the max of the release→apex and apex→hit angles). Both are measured in 3D with σ from one side-on camera, and the pack holds an `ittf_strict` variant (16 cm, a few degrees). This is a weekend MUST. (2026-10-24)
- **D-23: AI votes are off the live path.** Claude, Gemini and Bitdeer run in parallel and in the background, starting speculatively when a close `ensemble` call is posted, each with a 4 s timeout. Spoken calls and replays never wait on them; votes stream into the panel, and the judge decides. Why: three hosted vision calls cost about 1–4 s each (an estimate, measured in P0), so running them in series on the live path would break the ≤ 1.5 s call target. (2026-10-24)
- **D-24: Post-game Trophy Watch is in the weekend plan for every game we run** (the first SHOULD after C3), translated from Replay's Fire TV app (`apps/tv`, `packages/tv-core` @ `2db92c0`) to a web app. Moments are written live by the engine into Spacetime, video comes from the recorder's HLS, tv-core is vendored, and the D-pad, Alexa and phone-QR layers are dropped. The watch party is the only place clients call Spacetime reducers directly (scoped `watch_*` and `set_player_label`). Highlight scoring uses event features only, because the live stream carries no audio. Why: the user asked for post-game analysis for all games, and it strengthens the Spacetime, Moss, Cartesia, Anthropic and Meta tracks. (2026-10-24)
- **D-25: C0 contract choices.** (a) `ai_vote` is keyed by `(call_id, backend)` with a nullable `challenge_id`, because D-23 starts votes before any challenge exists. (b) Spacetime reducers that take rows accept one JSON-string argument (`post_observations(batch_json)` etc.), and the module parses and validates it; one reducer signature then survives schema growth, and the spike measured the same latency as typed arrays (Windows localhost, single runs). (c) Each backend writer has its own Spacetime identity token (`SPACETIME_VISION_TOKEN`, `_ENGINE_`, `_COMPILER_`), because the spike showed that an unauthenticated HTTP call still succeeds with a fresh random identity, so reducers must check `ctx.sender`. (d) Clients receive rows with `*_json` columns already parsed (`state.schema.json`). (2026-10-24, Agent 1)
- **D-26: The demo machine is the Windows 11 PC (Intel Core Ultra 5 125U, Intel Graphics iGPU, 15.4 GB), provided it's fast enough; this revises D-12's M5 Pro Mac.** The user asked on 2026-10-24 to use this PC "if it's fast enough". "Fast enough" is decided by Agent 2's tracker spike **on this PC** (≥ 25 fps at 720p, OPEN-3); if it misses, flight moves to the Mac or a Vultr GPU (user approval) and the rest stays here. Consequences: no MPS/CoreML (CPU, or OpenVINO/DirectML on the Intel GPU/NPU); the recorder uses `h264_qsv` (Intel Quick Sync, measured ≈ 108 fps encoding a 720p30 test pattern here) or `libx264` instead of `h264_videotoolbox`; there's no native Redis on Windows, so Redis runs in Docker Desktop or WSL; services still run natively per D-12. The HTTPS origin `https://trophy.photo` already runs here (Caddy + Porkbun DNS-01 → this PC's LAN IP). (2026-10-24, Agent 1 with the user)
- **D-27: Live calls use 720p30; challenges get phone-recorded high-quality clips.** The user asked whether to record 4K at a higher frame rate. A web page on iOS gets about 30 fps from the camera (the iPhone delivered 29.9), so higher frame rates need a native app, and 4K live is impractical: JPEG encode on the iPhone took 14.6 ms per 720p frame (9× the pixels at 4K), about 0.5 MB per frame (~100 Mbps per phone), heat, and no GPU on the demo PC for tracking it. So the live stream stays 1280×720 JPEG at 30 fps for the referee, while each camera phone captures at 1080p (default) or 4K (menu option) and records the full-quality track locally in rolling 6 s standalone segments (MediaRecorder, last 5 kept). When a challenge opens, each camera uploads only the segments covering the call's evidence window ±1 s (`POST /api/clips`); the judge's replay plays them at 1×, ½× or ¼× with frame steps. Clips stay in `data/local/clips/` (gitignored). This revives the plan's cut "phone-side recording upload" item in a narrow form. (2026-10-24, Agent 1 with the user)
- **D-28: The Droid's unit of work is a three-file sport module, and the compiler has no keyless mode.** `sports/<sport>/` holds `config.yaml` (detector parameters), `events.py` (layer 1 → layer 2, pure, import-allowlisted) and `rules.yaml` (the CEL rule pack); this replaces "the Droid edits one YAML in `rulepacks/`" (§18). The Droid derives new sports from the handwritten `sports/table_tennis/`, applies house rules to `rules.yaml` only, and retunes `config.yaml`/`events.py` on health alarms, always in a throwaway git sandbox with a file allowlist enforced by the runner, `replay_test` as the gate, a 90 s timeout and human approval. The compiler refuses to start without `FACTORY_API_KEY`; no stub or fallback backend is written until its own key exists (the Claude-only fallback is deferred). Agent 3's work is staged: 1 the Droid, 2 the engine, 3 replay/votes/ask. Why: the user asked for the Droid first and for no placeholder fallbacks (2026-10-24); a sport module gives the Droid a bigger, testable job (a whole sport, not one rule) while keeping perception measurements and rules separate (D-18). (2026-10-24, Agent 3)
- **D-29: Stage 2/3 engine choices.** (a) The score is replayed from the call log on every change (`final`, `upheld` and `challenged` calls count; `voided` and `overturned` do not; an overturn posts a replacement call that `supersedes` the original), so undo and overturn are exact and "first to 7" is a scoring-param change. (b) Rules run in pack order; several may fire on one event, but only the first scoring rule (kind point/violation/basket with points, or outcome `let`) ends the rally. The rally state exposes `at_fault_side` (the side the ball last bounced on, else the server) so "off the table" and "no return" rules don't need contacts. (c) `has(ev.payload.edge)` replaces `!= null` in CEL (cel-python has no null comparison for maps; the engine strips None values before evaluation). (d) decide() voters are constructed only with their keys; `trophy-engine run --votes` refuses to start if any of the three is missing, and the per-voter timeout is enforced by the fan-out, which never waits for a slow voter. (e) Moments are written by the engine as calls happen; `highlight_score` weights are listed in `moments.py` and every moment carries "scored from event features only (no crowd audio)". (f) Commentary and coach tips use Claude only with its key; a line that fails grounding becomes a template line marked `source: template` (the spec's fallback), never a line that pretends to be Claude's. (2026-10-24, Agent 3)
- **D-30: The Droid sandbox is enforced by a PreToolUse hook, with a direct-tool-mode model at autonomy "low".** Measured on 2026-10-24 with droid 0.249 / SDK 0.10: autonomy "off" offers no Edit/Create tools; autonomy "low" auto-approves file edits inside and outside the working directory without consulting the SDK permission handler; `claude-opus-5-5`, `claude-fable-5.1` and `gpt-6-sol` run in script-only tool mode where edits happen inside a script the handler cannot inspect. So every sandbox gets `.factory/hooks.json` → `services/compiler/hooks/guard.py` (exit 2 blocks; allowlisted files and `./replay_test` only), the runner audits `git status` after each turn and fails any run that touched anything else or nothing at all, script confirmations are refused, and `DROID_MODEL` defaults to `claude-sonnet-5` (direct mode, reasoning effort low) to fit the 90 s budget. Compile jobs start from a copy of the reference module. Why: the first live runs produced a false "ready" with an empty diff and a timeout retyping `events.py`. (2026-10-24, Agent 3)

# `@trophy/state-client`

`TrophyState` is the only state API the PWA and dashboard use (interfaces-v1 §11). Today it has one implementation, **`MockState`**, which plays **labelled-synthetic** scripts so UI work can start before the pipeline exists. `SpacetimeState` lands with the Spacetime module in P1, behind the same interface.

```ts
import { createState } from "@trophy/state-client";
import demo from "@trophy/state-client/fixtures/table-tennis-demo.json";

const state = createState("mock", { script: demo as MockScript, speed: 1, loop: true });
if (state.synthetic) showBanner(state.label); // required: synthetic data must be labelled in the UI
state.onCall((call, change) => …);   // insert, then updates (challenged → upheld/overturned)
state.onScore((scores) => …);
state.onAiVote((vote) => …);         // probabilities are uncalibrated: say so
state.onHouseRule((rule) => …);      // pending → compiling → ready → approved
state.onObservation((ev) => …);      // world state: vision observations (no video)
state.onTrackSample((s) => …);       // 10 Hz ball track
await state.connect(gameId);
```

Every `on*` first replays rows already known (as `"insert"`), then streams changes, like a Spacetime subscription.

## Fixtures (synthetic)
- `fixtures/table-tennis-demo.json` (~32 s): a legal serve and a long ball (AUTO), a toss too low (AUTO violation with a serve-toss overlay), an edge ball at 71 % (BETA) with three speculative AI votes, a challenge and an upheld verdict, a Droid house rule ("first to 7, win by 1") going pending → approved, and an ask-the-ref answer whose citation is a **placeholder**, not a real clause.
- `fixtures/basketball-demo.json`: three shots (2, 3, and a close 3 at 62 %).

They're generated by `scripts/build-fixtures.ts` (type-checked against the contracts) and validated against the schemas in CI. Rebuild with `make fixtures`.

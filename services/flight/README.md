# Flight: recorded table-tennis measurement path

The working local recorded demo is documented in [docs/tt-demo.md](../../docs/tt-demo.md). `flight/recording.py` provides PTS-preserving classical tracking, coarse shared-audio alignment, candidate activity boundaries and upward-only synthetic/validated toss geometry. `flight/blurball.py` adapts a checksum-pinned official model for native MPS; `flight/stereo.py` rejects metric reconstruction without trusted geometry/timing. `referee.py` is an isolated deterministic engine handoff, separate from all perception code.

Run `make tt-demo` for prepared playback or `make tt-demo-build` for conservative CPU preprocessing. The preferred model-derived local recording is rebuilt with `tools/track_tt_blurball.py --gray --suffix blurball-gray` and selected with `tools/build_tt_demo.py --detector blurball-gray --skip-preview`. The current experimental local playback adds observed color fallback via `tools/fuse_tt_tracks.py` and `tools/build_tt_demo.py --detector hybrid --skip-preview`; no held-out hybrid accuracy or joint throughput is claimed. Public use of BlurBall weights is not approved; no weights are versioned. Inference dependencies are pinned in `requirements-demo.txt`.

The Redis live reader/event loop is not implemented. `tools/play_clip.py` publishes source frames and `tools/export_tt_observations.py --publish` can mirror exported measurement metadata through the existing shared writers; neither live path is claimed tested. Real serving/edge/winner automation has not passed validation on the supplied moving-camera clips. Missing evidence remains unresolved. See `docs/status/a2.md` for measured results and the production handoff.
